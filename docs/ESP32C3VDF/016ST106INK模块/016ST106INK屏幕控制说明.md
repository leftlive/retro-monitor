# 016ST106INK VFD 屏幕显示元素控制总结

本文档基于对 `016ST106INK` 屏幕模块的实际逆向测试以及厂商提供的阳极连接表（ANODE CONNECTION）整理得出。该屏幕虽然底层使用的是类似于标准 16G 的 VFD 驱动方案，但在具体的硬接线上包含了许多专门针对音频功放设计的"隐藏设计"。

## 一、 整体显示矩阵 (DCRAM)

这块屏幕拥有两行字符显示区域，也就是硬件对应的 **Matrix A (A矩阵)** 和 **Matrix B (B矩阵)**。

### 1. Line 1 (上半行，对应 B 矩阵 `D0B - D34B`)
*   **网格 1G - 8G**：拥有完整的 5x7 像素点阵。在程序中用来显示 `CPU|GPU|`（第一屏）或 `MEM|FAN|`（第二屏）。
*   **网格 9G - 14G**：**不包含任何点阵段！** 发送给此区域的数据不会点亮任何常规字符。
*   **网格 15G - 16G**：同样没有完整的 5x7 像素段，但存在一个**极度特殊的硬件映射设计**：
    *   该区域的 **D33B** 触点（位于第 4 列第 7 行）被接线到了固定字母 **`P`** 上。
    *   该区域的 **D34B** 触点（位于第 5 列第 7 行）被接线到了固定字母 **`A-B`** 上。
    *   **控制技巧**：由于 15G 和 16G 没有其它常规点阵，我们可以通过发送特定的 ASCII ROM 字符来精准控制底部的像素。例如发送下划线 `0x5F` (`_`) 会点亮第 7 行全部列，从而同时点亮 `P` 和 `A-B`；发送反斜杠 `0x5C` (`\`) 则由于边缘切割，只会碰触到第 5 列，从而变成只亮 `A-B` 而不亮 `P`。
    *   **注意**：切勿对这段区域发送 `0x7F` (Delete控制码)，多数主控芯片会将其强制解读为硬件闪烁光标，导致图标不受程序控制地胡乱闪烁。

### 2. Line 2 (下半行，对应 A 矩阵 `D2A - D34A`)
*   **网格 1G - 16G**：**全域拥有完整的 5x7 像素点阵**。
*   第一屏显示温度、负载及功率；第二屏显示内存占用、风扇转速及功率。

## 二、 固定长条字幕/图标控制 (ADRAM)

屏幕右侧区域密集排列了诸如 `STEREO`、`MUTE` 等大面积的丝印单词，这些是通过底层驱动额外的 **4个 AD 控制位 (AD1 ~ AD4)** 单独进行寻址控制的。它们完全独立于普通的 5x7 点阵，每个网格 (Grid) 拥有四个布尔值开关。

经过抓包与照片交叉比对，正确的硬件乱序排列映射规律（真理表）如下：

| 网格 (Grid) | AD1 (引脚 D0) | AD2 (引脚 D1) | AD3 (引脚 D2) | AD4 (引脚 D3) |
| :--- | :--- | :--- | :--- | :--- |
| **9G,  10G** | `TUNED` | `STEREO` | - | - |
| **11G, 12G** | `SP B`  | `SP A`   | - | - |
| **13G, 14G** | `SLEEP` | `MUTE`   | - | - |
| **15G, 16G** | 随机 (交叉箭头) | 循环 (圈状箭头) | 数字 **`1`** | 字母 **`F`** |

### 当前运行时图标逻辑

| 图标 | 行为 | 说明 |
| :--- | :--- | :--- |
| `STEREO` / `TUNED` | 常亮 | 装饰性指示灯 |
| `SP A` | 第二屏时亮起 | 页面指示器（MEM/FAN 屏） |
| `SP B` | 第一屏时亮起 | 页面指示器（CPU/GPU 屏） |
| `MUTE` / `SLEEP` | 常亮 | 装饰性指示灯 |
| `1` / `F` | 1Hz 闪烁 | 系统心跳指示 |
| `P` | 与 `1F` 同步闪烁 | 通过 `0x5F`/`0x5C` ROM 字符切换控制 |
| `A-B` | 常亮 | 通过 `0x5C` 始终保持右下像素触发 |

## 三、 自定义动态字模 (CGRAM)

屏幕内置了自定义显存（CGRAM），支持 **8 个** 自定义图案（索引号为 `0 ~ 7`）。

### 1. 突破高度限制
标准的控制指令大多适配 5x5 的小字模，为了实现类似赛博朋克风格的"通顶分隔线"，必须改写 CGRAM 的映射方法（即重构 `write_cgram_7x5` 函数），将字模控制释放到 7 个完整的物理像素高度。

### 2. 本项目现用槽位设计
*   **0~3**：4px 宽度、左下角对齐的极简风格字母 `C`、`P`、`U`、`G`。
*   **4**：闪烁分隔符 (`GLYPH_SEP_BLINK_ON`)，7px 高右侧通顶竖线 + 左下角 `2x2` 方块。
*   **5**：摄氏度符号 `℃`。
*   **6**：能量闪电符号 `⚡`。
*   **7**：纯净通顶分隔竖线 (`GLYPH_SEP_BLINK_OFF`)，闪烁交替态及第二行常驻分隔线。

## 四、 电源管理

### 自动息屏
*   当 3 分钟内未收到任何 Home Assistant 遥测数据时，系统自动调用 `set_power(false)` 关闭 VFD 高压。
*   同时停止所有 UI 渲染以降低 MCU 功耗。

### 自动唤醒
*   当 `cpu_temp` 传感器接收到新的数据推送时，立即调用 `begin(0xE0)` 执行完整的硬件重初始化（包括时序、亮度、CGRAM 字模恢复）。
*   **注意**：仅调用 `set_power(true)` 不足以唤醒屏幕，因为 VFD 控制器在断电后会丢失全部内部寄存器状态。

## 五、 最佳实践与踩坑防范总结
1. **不要想当然地按顺序推测**：很多面板在玻璃内部走线时为了不跨线，会大幅度扰乱网格顺序（如 `1` 和 `F` 被连在 15G 网格上，而不是顾名思义的右上角最边缘）。**必须完全遵循真理表**。
2. **警惕像素点接线复用**：就像 `P` 和 `A-B` 本身属于独立的字符系统，却通过占用屏幕最边角点阵矩阵的底边"伪装"成了右上角的一部分。利用 `ROM` 中携带特定底部像素的特殊字符（如下划线、反斜杠）去触碰它们对应的电路，是不破坏布局的前提下最好的一种隔离打法。
3. **唤醒必须完整初始化**：VFD 控制器断电后会丢失所有状态，唤醒时必须执行 `begin()` 而非仅 `set_power(true)`。
4. **避免在 lambda 中使用阻塞式 `delay()`**：会冻结 WiFi 协议栈导致断连。应使用 ESPHome 原生的 `- delay: Xms` 动作。
